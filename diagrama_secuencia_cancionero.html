Flujos de interacción entre componentes y Firestore

Flujo: Abrir una canción desde el catálogo

  • 1. Usuario toca nombre de canción
  • 2. Se invoca abrir(id, false) → estado local
  • 3. Se invoca pintarLector() para renderizar

Flujo: Director transmite una canción

  • 1. Director toca botón "Transmitir" (o "Online")
  • 2. Se invoca transmitirDesdeElPrincipio()
  • 3. Escribe en Firestore: cancionero/directorEnVivo
  • 4. Los listener de otros dispositivos disparan escucharDirector()
  • 5. Todos abren automáticamente la canción en vivo

Flujo: Agregar una canción a la lista del evento

  • 1. Usuario toca "+" en el buscador o menú
  • 2. Se invoca alternarEnLista(id)
  • 3. Se agrega/quita id del array est.lista.ids
  • 4. Se escribe en Firestore: reuniones/{id}
  • 5. El listener de otros dispositivos dispara
  • 6. Todos ven la canción nueva en la lista

Flujo: Dos dispositivos transmiten simultáneamente

  • 1. Dispositivo A escribe su transmisión en Firestore
  • 2. Dispositivo B también escribe (posible conflicto)
  • 3. Firestore usa merge:true para no pisar datos
  • 4. Campo directoresLatido usa increment() (operación atómica)
  • 5. Gana la última escritura si dos modifican campos distintos

Flujo: Editar acordes o letra de una canción

  • 1. Usuario toca "Editar" desde menú
  • 2. Se invoca abrirEditor(id)
  • 3. Se cargan datos actuales en el formulario
  • 4. Usuario modifica y toca "Guardar"
  • 5. Se invoca guardarEditor()
  • 6. Escribe en Firestore: canciones/{id}
  • 7. Recalcula catálogo y actualiza vista

Flujo: Crear un nuevo evento

  • 1. Usuario toca "+ Nuevo evento"
  • 2. Se invoca crearReunion()
  • 3. Se genera idReunion único
  • 4. Se crea doc en Firestore: reuniones/{idReunion}
  • 5. Se setea como activo: cancionero/activa = {reunionActivaId}
  • 6. Todos los listeners notan el cambio de reunión activa
  • 7. App navega a pestaña Evento con lista vacía
