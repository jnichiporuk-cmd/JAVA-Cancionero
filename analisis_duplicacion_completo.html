Búsqueda de patrones repetidos que podrían centralizarse (como filtrarCanciones)

Análisis de todas las funciones render() para detectar lógica duplicada que se pueda centralizar.

Patrones encontrados: 10 duplicaciones
Prioridad ALTA: 3 (afectan funcionalidad)

🔥 Prioridad ALTA (Afectan Funcionalidad)

1. Generar filas de canciones (3 lugares)
La construcción de HTML para una fila de canción está repetida en:
  • renderCatalogo() — línea ~1746
  • renderAgregar() — línea ~2086
  • renderReunion() — línea ~1800
// Los tres generan HTML similar:
fila.innerHTML = `
  <button class="fila-txt">
    <div class="fila-nombre">${escapar(s.nombre)}</div>
    <div class="fila-meta">${metaDe(s)}</div>
  </button>
  <button class="...">${icono}</button>`;
Impacto: Si cambias el formato de filas, tocas 3 lugares. Si falta metaDe(), rompe en los 3.
Solución: Crear function filaCancion(s, opciones) que devuelva HTML formateado.
Líneas: 1746, 1800, 2086 | Complejidad: Media
2. Escapar HTML y mostrar nombre (2 lugares)
En varias funciones se hace escapar(s.nombre) para evitar XSS. Pero hay:
  • Filas de canciones en renderCatalogo/Agregar/Reunion (3 lugares)
  • Menús dinámicos que generan opciones HTML
// Repetido:
<div class="fila-nombre">${escapar(s.nombre)}</div>
<div class="fila-nombre">${escapar(s.nombre)}</div>
<div class="fila-nombre">${escapar(s.nombre)}</div>
Impacto: Si olvidás escapar() en uno, hay XSS. Si quieres cambiar el formato del nombre, tocas muchos lugares.
Solución: function mostrarNombre(s, truncar = false) que maneja escapado y truncado.
Líneas: 1748, 1800, 2088 (y más) | Complejidad: Baja
3. Obtener metadatos de canción (2+ lugares)
metaDe(s) se llama en todas las filas. Pero el formato está hardcodeado y se repite: 
// metaDe devuelve:
`<span class="fila-meta">...</span>`

// Se usa:
<div class="fila-meta">${metaDe(s)}</div>
Impacto: Si quieres cambiar qué metadatos mostrar (hoy: tono + BPM), editas metaDe() y se actualiza en todos lados. ✅ Esto YA está bien.
Estado: ✅ No necesita refactor (ya centralizado).
Función: metaDe() línea ~2306 | Complejidad: Ya optimizado

⚠️ Prioridad MEDIA (Mantenimiento)

4. Mensajes de "vacío" (3 lugares)
Cuando una lista está vacía, se muestra un mensaje. Hay 3 variantes: 
// renderCatalogo() - Sin resultados
"Sin resultados. Probá con parte del nombre, o con el tono (G, Bm)."

// renderAgregar() - Sin resultados
"Sin resultados. Probá con parte del nombre, o con el tono (G, Bm)."

// renderReunion() - Todavía no hay lista
"Todavía no hay lista. Tocá \"+ Agregar canción\"..."
Impacto: Ya centralizamos parcialmente en TEXTOS. Pero faltan los otros.
Solución: Extender TEXTOS con todos los mensajes vacíos.
Líneas: 1721, 2078, 1765 | Complejidad: Baja
5. Renderizar menús desplegables (3 variantes)
Hay 3 menús distintos con lógica similar:
  • mostrarMenuCancion() — Menú de canción en evento
  • mostrarMenuCancionCatalogo() — Menú de canción en catálogo
  • mostrarMenuReunion() — Menú de reunión guardada
// Todos hacen básicamente:
const menu = document.createElement("div");
menu.className = "menu-dropdown";
opciones.forEach(op => {
  const btn = document.createElement("button");
  btn.textContent = op.label;
  btn.onclick = op.action;
  menu.appendChild(btn);
});
Impacto: Si quieres cambiar estilo/clase de menú, tocas 3 funciones.
Solución: function mostrarMenu(opciones, posicion) centralizado.
Líneas: 1861, 1951, 2172 | Complejidad: Media
6. Validación de entrada (duplicado en algunos places)
Hay validaciones que se repiten:
  • trim().toLowerCase() — En búsquedas (ahora centralizado ✅)
  • RE_TONO_VALIDO.test() — En editor + transporte (2+ lugares)
  • Validar nombre no vacío — En 3+ funciones de guardar
Impacto: Si cambias el regex de tonos, tocas múltiples lugares.
Solución: Crear function validarTono(s), function validarNombre(s).
Líneas: 2824, 2839, 2857, 1354 | Complejidad: Baja
