🔧 Refactor: Unificar Función "Editar"

Análisis de cómo combinar Editar Canción y Editar Evento en una sola estructura reutilizable

❌ Estado Actual (Repetido)

Editar Canción

abrirEditor(id)
  → Carga: nombre, tono, BPM, bloques (acordes + letra)
  → Mostrar vista previa de bloques
  → Botón "Transportar" (cambiar tono de toda la canción)
  → Guardar: guardarEditor()
  → Eliminar: borrarCancion() (opcional)

guardarEditor()
  → Validar nombre, tono, bloques
  → Crear canción: {id, nombre, tono, bpm, bloques}
  → Guardar en est.cambios.editados[] o est.cambios.nuevas[]
  → recalcular() → pintar()

Editar Evento

abrirEditarReunion(id) / abrirNuevaReunion() / abrirCopiarReunion(id)
  → Carga: nombre, fecha, hora
  → Validar nombre
  → Guardar: guardarEditarReunion()

guardarEditarReunion()
  → Validar nombre
  → Crear reunión: {id, nombre, fechaReunion, ...}
  → Escribir en Firestore: reuniones/{id}
  → actualizar cancionero/activa
  → recalcular() → pintar()
Problema: Son funciones totalmente separadas aunque siguen el mismo patrón: abrir → llenar campos → validar → guardar. Duplican lógica de formulario y guardado.

2. Función genérica: abrirEditor(tipo, id, opcion)

function abrirEditor(tipo, id, opcion = null) {
  // opcion: null (editar), "nueva" (crear), "copiar" (duplicar)

  const esquema = TIPOS_EDITAR[tipo];
  if (!esquema) return flotar(`Tipo desconocido: ${tipo}`);

  est.editando = { tipo, id, opcion };

  // Determinar título
  const es_nueva = (id === "nueva" || opcion === "nueva");
  const titulo_fn = esquema.titulo || (() => "Editar");
  $("editor-titulo").textContent = titulo_fn(es_nueva);

  // Cargar datos según el tipo
  let datos = {};
  if (!es_nueva) {
    if (tipo === "cancion") {
      const cancion = PORID[id];
      if (!cancion) return flotar("Canción no encontrada");
      datos = {
        "ed-nombre": cancion.nombre,
        "ed-tono": cancion.tono || "",
        "ed-bpm": cancion.bpm || "",
        "ed-cuerpo": bloquesATexto(cancion.bloques)
      };
    } else if (tipo === "evento") {
      const evento = /* buscar evento */;
      if (!evento) return flotar("Evento no encontrado");
      datos = {
        "er-nombre": evento.nombre,
        "er-fecha": formatearFecha(evento.fechaReunion),
        "er-hora": formatearHora(evento.fechaReunion)
      };
    }
  }

  // Llenar campos (genérico)
  esquema.campos.forEach(campo => {
    const el = $(campo.id);
    if (el) el.value = datos[campo.id] || "";
  });

  // Controles especiales
  if (esquema.especial === "transporte") {
    mostrarBotonesTransporte();
  }

  // Botón eliminar
  if (esquema.mostrarEliminar) {
    $("ed-borrar").style.display = es_nueva ? "none" : "block";
  }

  $("editor").classList.add("abierto");

  // Previsualizaciones específicas del tipo
  if (tipo === "cancion") refrescarPrevia();
}

3. Función genérica: guardarEditor()

async function guardarEditor() {
  const { tipo, id, opcion } = est.editando;
  const esquema = TIPOS_EDITAR[tipo];

  // Recolectar valores de todos los campos
  const datos = {};
  esquema.campos.forEach(campo => {
    const el = $(campo.id);
    datos[campo.id] = el ? el.value.trim() : "";
  });

  // Validar requeridos
  for (const campo of esquema.campos) {
    if (campo.requerido && !datos[campo.id]) {
      return flotar(`Falta: ${campo.label}`);
    }
  }

  // Dispatch al guardado específico del tipo
  if (tipo === "cancion") {
    await guardarCancion(id, opcion, datos);
  } else if (tipo === "evento") {
    await guardarEvento(id, opcion, datos);
  }

  cerrarEditor();
}

async function guardarCancion(id, opcion, datos) {
  const tono = datos["ed-tono"];
  if (tono && !RE_TONO_VALIDO.test(tono)) {
    return flotar(`"${tono}" no parece un tono`);
  }

  const bloques = textoABloques(datos["ed-cuerpo"]);

async function guardarEvento(id, opcion, datos) {
  const nombre = datos["er-nombre"];

  let fechaReunion = Date.now();
  const fechaStr = datos["er-fecha"];
  if (fechaStr) {
    const [anio, mes, dia] = fechaStr.split("-").map(Number);
    const [h, mi] = (datos["er-hora"] || "00:00").split(":").map(Number);
    fechaReunion = new Date(anio, mes - 1, dia, h, mi).getTime();
  }

  const idReunion = id === "nueva" ? generarIdReunion() : id;

  const evento = {
    id: idReunion,
    nombre,
    fechaReunion,
    ids: [],
    creada: Date.now(),
    actualizada: Date.now()
  };

  // ... resto del guardado (igual que ahora)
  await db.collection("reuniones").doc(idReunion).set(evento);
}

⚠️ Riesgos y Consideraciones

Validación específica

Hoy cada tipo tiene validaciones diferentes (ej: RE_TONO_VALIDO para canción, no para evento). Hay que asegurar que eso se mantenga en guardarCancion() y guardarEvento() específicamente, no en guardarEditor() genérico.

Campos dinámicos complejos

Canción tiene botones de "Transporte" (♭/♯) que evento no tiene. La lógica esquema.especial es simple pero si hay muchas diferencias, se vuelve frágil. Considerar si vale el esfuerzo.

HTML del formulario

Buena noticia: hoy el HTML ya está hecho con dos "editores" separados (#editor para canción, #er-editar para evento). Se pueden consolidar en uno solo (#editor) que pinte dinámicamente según el tipo. Pero eso es un refactor aparte (más chico).

Rollback seguro

La vieja lógica está clara. Si algo falla, es fácil revertir paso a paso (primero la estructura, después los calls).

💡 Alternativa (más conservadora)

Si unificar completamente es mucho riesgo, hacer una refactor más pequeña:

  • Crear función validarDatos(tipo, datos) compartida
  • Crear función llenarFormulario(tipo, datos) compartida
  • Dejar abrirEditor() y guardarEditor() tal como están, pero que usen esas funciones comunes

Esto reduce repetición (~20% de ahorro) con menos riesgo que la refactor completa (~50% de ahorro).

✅ Conclusión

La refactor de "Editar" es viable y recomendada porque:

  • ✅ Baja complejidad: solo son 2 tipos, el patrón es claro
  • ✅ Alto beneficio: elimina ~100 líneas de código repetido
  • ✅ Fácil mantener: agregar un nuevo tipo es agregar una entrada al esquema
  • ✅ Bajo riesgo: la lógica específica se mantiene separada
  • ✅ Pasos claros: son 7 pasos chicos, testeable cada uno

Recomendación: Hacer la refactor completa. Es un buen primer paso para identificar más oportunidades de unificación (Cerrar, Guardar, Buscar, Menús).
