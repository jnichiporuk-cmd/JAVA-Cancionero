🏷️ Análisis: Nomenclatura y Constantes Duplicadas

¿Por qué se llaman "pintar"? ¿Por qué no centralizar los placeholders?

❓ ¿Por qué se llaman "pintar"?

Es un término heredado de interfaz gráfica (GUI). Significa "renderizar" o "dibujar en pantalla".

En el código:

Función Qué hace Nombre alternativo
pintarCatalogo() Renderiza lista de canciones renderCatalogo() / updateCatalogo()
pintarReunion() Renderiza lista del evento renderMeeting() / updateEvent()
pintarLector() Renderiza vista de canción renderSongView() / updateReader()
pintarAgregar() Renderiza panel de búsqueda renderAddPanel() / updateAddSongs()
pintar() Renderiza TODO según estado render() / updateUI() / refreshUI()
✅ "Pintar" es común en código español
En proyectos hispanohablantes es un término reconocido. No es incorrecto, es una convención.
⚠️ Pero tiene problemas:
  • Inconsistencia: Hay también actualizarNumerosOrden(), actualizarColapsoTope(), etc. Mezcla "pintar" con "actualizar"
  • Menos claro en inglés: Si alguien de otro país lee el código, "pintar" no es obvio
  • Buscar es confuso: "paint" en Google tiene muchos resultados, "render" es más específico

Opciones para mejorar:

Opción 1: Renombrar a "render" (más estándar)
renderCatalogo()      // Más claro internacionalmente
renderReunion()
renderLector()
renderAgregar()
render()             // Función principal

✅ Estándar en React/Vue/Svelte. Claro qué hace. ❌ Requiere cambiar ~40 referencias en el código.

Opción 2: Mantener "pintar" pero hacer consistente
// Cambiar actualizar* → pintar*
pintarNumerosOrden()       // No actualizarNumerosOrden()
pintarColapsoTope()        // No actualizarColapsoTope()
pintarVisibilidadPie()     // No actualizarVisibilidadPie()
pintarBotonesTransporte()  // No actualizarBotonesTransporte()

✅ Consistencia total, menos cambios que opción 1. ✅ Mantiene la convención española del proyecto. ❌ Sigue siendo menos claro que "render".

Opción 3: Dejar como está (conservador)
// Sin cambios

✅ Cero riesgo, funciona bien. ❌ Inconsistencia + confusión futura.

📋 Placeholders Duplicados

Tienes razón. El placeholder está en el HTML hardcoded en dos lugares:

Línea Input Placeholder
505 id="buscar" "Buscar por título, letra, tono o BPM"
617 id="ag-buscar" "Buscar por título, letra, tono o BPM"
El problema real

Si mañana quieres cambiar "Buscar por..." a "Encontrar...", tocas 2 líneas de HTML en lugar de 1.

Y si los textos se desincronizaban (una dice "título, letra" y la otra dice solo "título"), causaría confusión.

Solución: Constante centralizada

// Al inicio del script (después de CATALOGO_BASE)
const TEXTOS = {
  placeholder_buscar: "Buscar por título, letra, tono o BPM",
  vacio_catalogo: "Sin resultados. Probá con parte del nombre, o con el tono (G, Bm).",
  vacio_agregar: "Sin resultados. Probá con parte del nombre, o con el tono (G, Bm).",
  vacio_evento: "Todavía no hay lista",
  // ... más textos comunes
};

Nota: El placeholder está en HTML, no en JS. Para usarlo tendrías que genrar el HTML dinámicamente, lo cual es un cambio más grande.

Alternativa más práctica:

Mantener los placeholders en HTML (como ahora) pero asegurarse de que sean exactamente idénticos con un comentario que diga por qué:


<input id="buscar" type="search"
  placeholder="Buscar por título, letra, tono o BPM"
  autocomplete="off">


<input id="ag-buscar" type="search"
  placeholder="Buscar por título, letra, tono o BPM"
  autocomplete="off">

Así en el futuro, si alguien edita uno, sabe que tiene que editar el otro también.

✅ Resumen

"Pintar" vs otros nombres:

  • Estado actual: Mezcla "pintar" con "actualizar" (inconsistente)
  • Mejor opción: Renombrar todo a render*() (más claro, estándar)
  • Alternativa: Hacer consistente: todo "pintar" o todo "actualizar"
  • Realidad: El nombre no afecta funcionalmente, es cosmético

Placeholders duplicados:

  • Estado actual: Mismo texto en 2 lugares del HTML (duplicación)
  • Mejor opción: Constante JS TEXTOS.placeholder_buscar
  • Alternativa práctica: Comentario en HTML que diga "debe ser idéntico a id=buscar"
  • Prioridad baja: No causa bugs, solo mantenimiento futuro

2. ⚠️ Renombrar a "render" Legibilidad + consistencia, cambio cosmético
